## Gemini diagnosis boundary

The previous committed implementation used a hand-built REST request whose endpoint and request shape appear compatible with Gemini's GenerateContent API. That code discarded provider response bodies/statuses and did not retry transient errors, so a historical failure cannot be assigned to a specific credential, quota, network, model, or request cause from repository evidence. A later live request reached Gemini and returned HTTP 429. The status confirms provider-side throttling or quota enforcement, but the exact reason (RPM, input TPM, daily quota, usage/billing tier, or temporary capacity) was not retained. Current diagnostics keep provider status/code/category, safe quota dimensions, and retry delay when available without logging prompt bodies or credentials. Check the selected project's active model quota and usage in Google AI Studio before changing the model or billing settings.
